# BOSS 直聘 · 筛选巡航助手

一个针对 [BOSS 直聘职位搜索页](https://www.zhipin.com/web/geek/jobs) 的 Chrome 扩展（Manifest V3）。
我超，本来看着APP可以筛选是否双休网页端却不行，想着网页端接口应该是有相关字段的，结果一开控制台分析接口就疯狂刷新。
用别的办法拿到接口信息之后发现根本没有相关字段，合着真就跟在职的时候听说的一样，网页端版本早就落后APP很久了，而且基本只维护不更新，老东家属实有点摆烂了。无奈只能根据关键词转而去筛出外包岗位进行标红，顺带保留一下筛选条件，省的每次进页面都要重筛。

它解决三件事：

1. **同步筛选条件** —— 你在页面上点选的筛选（薪资 / 经验 / 学历 / 城市…），扩展会如实读到并显示出来。
2. **保存为默认** —— 把当前这套条件存下来。
3. **自动回填** —— 之后每次打开搜索页，自动套用保存的条件，不用再点一遍。

---

## 它为什么有用

BOSS 直聘本身不提供"只看双休"之类的维度，也不提供"排除外包"的筛选。平台的筛选码表里根本没有这些选项，所以你没法用官方筛选器过滤掉它们。

这个扩展从**招聘方自己写出来的文字**里找线索，命中就在列表上标出来，让你一眼跳过。

---

## 安装

1. 打开 `chrome://extensions`，右上角开启 **开发者模式**。
2. 点 **加载已解压的扩展程序**，选择本目录。
3. 打开 `https://www.zhipin.com/web/geek/jobs`。
4. 页面右下角出现 `LCS 筛选巡航` 面板，说明已生效。

建议先登录 BOSS 直聘再使用 —— 列表数据需要登录会话。

---

## 使用

### 同步与保存筛选条件

在页面上正常点选筛选条件，扩展会从页面真实请求里读到它们，面板和扩展图标弹窗都会显示出来。

点扩展图标 → **保存为默认**。

> 城市**不会被保存**。城市是你此刻所在的位置，不是要长期沿用的条件 —— 否则你换城市后会被强行改回去。弹窗会明确提示这一点。

### 自动回填

之后每次进入搜索页，扩展会自动套用保存的条件。

如果你当前 URL 里已经带了筛选条件（说明你正在手动筛选），扩展**不会覆盖**你的操作 —— 你的即时意图优先。

### 派遣 / 外包标红

开启「标红派遣/外包岗位」后，被判定为派遣或外包的岗位卡片会整体标红：

- 左侧粗红条 + 浅红底
- 岗位名变红
- 右上角挂一个徽章，**标出命中的具体词**，例如 `派遣/外包 · 外包`

把鼠标停在徽章上，会说明是命中「岗位名」还是「公司名」—— 判定理由是可追溯的，而不是一个无从核实的红块。

### 开关

| 开关 | 默认 | 说明 |
| --- | --- | --- |
| 标红派遣/外包岗位 | 开 | 关闭后不再标记，但筛选同步照常工作 |
| 宽松匹配 | 关 | 额外扫描福利与技能标签。**可能明显增多误报**，按需开启 |
| 进入页面自动应用筛选 | 开 | 关闭后每次进入都从空白开始 |

### 面板可拖动

右下角的面板按住标题栏即可拖动，位置会被记住，刷新后仍在原处。拖到屏幕外会被自动拉回可见区域。

### 自证：它凭什么这么说

扩展图标弹窗底部有 **接口日志**，列出最近 40 次接口调用及其返回码。

这里能直接看到列表接口是 `code 0`（正常）还是 `code 37`（被风控拦截），判定数据来自哪一次响应一目了然。**你不需要相信我的说法，可以自己核对。**

## 判定依据与边界

这一节讲清楚这个功能**能做到什么、做不到什么**。它没有你想象的那么强，这一点我不想含糊。

### 判定依据

只看两个位置：

- **岗位名** —— 如 `Java开发工程师(外包)`
- **公司名** —— 如 `某某人力资源服务有限公司`

刻意**不看职位描述**。描述里出现"该项目已外包给客户""有外包项目管理经验"是正常叙述，拿来判定会造成大量误报。

判定词包括：`派遣`、`外包`、`劳务派遣`、`人力资源服务`、`灵活用工`、`外派`、`驻场`、`乙方`、`劳务` 等。

同时会**主动排除**反向表述：`非外包`、`不是外包`、`甲方直招`、`正式编制`、`自有员工` 等 —— 这些是招聘方用来吸引人的卖点，判成外包会造成方向相反的误导。

### 已知的局限

**名字里不含关键词的外包公司判不出来。** 例如"中软国际"—— 它大量承接外包业务，但公司名里没有"外包""派遣""人力资源"任何一个词，匹配不到。

这不是缺陷，是字符串匹配的能力上限。要突破它需要引入外部数据（比如维护一份已知外包公司名单），那是另一个量级的工作。

**所以这个功能的定位是「招聘方自己承认的才算」，不是「替你识破所有外包」。**

### 哪些词比较容易误报

`驻场`、`乙方`、`劳务`、`外派` 这几个词语义比"外包"宽：

- 驻场可能指技术支援（不一定是外包）
- 劳务可能只是描述劳务关系

如果你发现误报偏多，**可以先关掉「标红」只保留筛选同步**，或者把具体例子反馈给我 —— 针对性调词表比笼统放宽有效得多。

## 常见问题

**面板没出现 / 按钮点了没反应？**
刷新一次页面。扩展更新后，已打开的标签页需要刷新才能注入新代码。

**扩展图标弹窗显示"脚本未就绪"？**
同上，刷新页面即可。

**标红失效了？**
BOSS 直聘改版可能换了 DOM 结构。弹窗的接口日志能看到接口是否正常；如果接口返回 `code 0` 但卡片没标红，多半是页面结构变了，把情况反馈给我。

**接口一直返回 `code 37`？**
这是平台的**环境风控**，不是登录问题。页面自己的请求正常，而扩展发出的请求可能被识别。表现为筛选同步正常但岗位数据拿不到。稍等几分钟再刷新通常可恢复。

**保存了条件，但换城市后没生效？**
这是设计如此 —— 城市不入库，跟随你当前位置。其他条件会照常套用。

**为什么没有"只看双休"？**
BOSS 直聘的数据里几乎没有这个信息。招聘方极少填写它，判定出来几乎全是"未知"，功能没有价值，已移除。

**它会上传我的数据吗？**
不会。所有数据留在本地浏览器，不联网、不上传。
